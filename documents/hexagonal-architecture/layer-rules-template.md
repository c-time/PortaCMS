# レイヤールール記述テンプレート

このテンプレートは、各レイヤー（Domain、Application、Infrastructure、Presentation、Bootstrap）における実装ルールを統一された形式で記述するためのガイドラインです。

## テンプレート構成

各レイヤールールファイル（`*-layer.md`）は、以下の構成に従って記述します：

1. **レイヤー内のフォルダ・ファイル構造の提示**
2. **サンプルコードの提示**（全体像を最初に提示）
3. **ルールの記述**（サンプルコードの一部を引用）
4. **チェックリスト**

## テンプレート記述ガイド

### 構成要素の詳細

#### 1. レイヤー名と説明
- タイトルにレイヤー名と簡潔な説明を記載
- 冒頭の引用ブロック（`>`）でレイヤーの役割を一言で表現
- 例: `> **Domain は「アプリの心臓部」。** 入出力やUI/フレームワークの事情から切り離し、純粋な型・規約・ロジックだけで構成します。`

#### 2. ルールセクション
各ルールは以下の要素で構成します：

- **説明**: 技術的な詳細と実装方法を記述
  - 何を定義しているのか
  - どのように実装するのか
  - フォルダ構造やファイル構成

- **意図**: 目的、利点、解決する問題を記述
  - なぜこのルールが必要なのか
  - どのような問題を解決するのか
  - どのような利点があるのか

- **フォルダ構造**: 抽象的なディレクトリ構造（必要に応じて）
  - プレースホルダー（`{AggregateName}`など）を使用
  - ファイルごとの役割を `#` コメントで説明

- **サンプル構造**: 具体的な例（必要に応じて）
  - 実際の具体例（`Project`、`User`など）
  - ファイルの具体的な内容を示す

- **サンプル**: TypeScriptコード例
  - ファイルパスをコメントで明示
  - セクション区切りのコメント（`// ========================================`）を使用
  - 重要なポイントにインラインコメントを追加

#### 3. サンプルコードの記述ルール

```typescript
// ファイルパスを明示
// 例: domain/Project/entities.ts

// ========================================
// セクション名（機能ごとにグループ化）
// ========================================

// インラインコメントで重要なポイントを説明
export const ExampleSchema = z.object({
  // フィールドごとに説明を追加（必要に応じて）
  id: z.string().uuid('説明'),
});

// ファクトリ関数やクラスの役割を説明
export function createExample(input: ExampleInput): Example {
  // 実装の重要なポイントを説明
  return ExampleSchema.parse(input);
}
```

#### 4. チェックリスト（各ルールごと）
- **各ルールの直後に配置**: そのルールに関連する確認項目のみを記載
- 実装時に確認すべき項目をリスト化
- 2〜3項目程度を目安に（ルールの複雑さに応じて調整）
- ✅ 絵文字を使用して視認性を向上
- 疑問形で記述（「〜しているか？」）
- そのルールを正しく実装できているかを直接確認できる内容

#### 5. アンチパターン（各ルールごと）
- **各ルールの直後に配置**: そのルールに違反する典型的な間違いを記載
- やってはいけないことと、正しいやり方をセットで記載
- 1〜2項目程度を目安に（ルールごとの代表的な間違い）
- ❌ 絵文字を使用して視認性を向上
- カッコ内に正しいやり方を記述
- そのルールに直接関連する具体的な例を示す

### 記述の一貫性ガイドライン

1. **セクション番号の調整**
   - `X.1`、`X.2`などの番号は、各レイヤーの章番号に合わせて調整
   - 例: Domain層の場合は `4.1`、Application層の場合は `6.1`
   - ルールセクションは `X.3` から開始（`X.1` はフォルダ構造、`X.2` はサンプルコード全体像）

2. **サンプルコードの提示方法**
   - **X.2セクション**: 全体像を最初に提示（複数のファイルにまたがる完全なサンプル）
   - **X.3以降のルールセクション**: 該当箇所のみを引用して説明
   - 各ルールでは、「該当サンプル」として上記サンプルコードの一部を引用
   - 引用時には、どのファイルのどの部分かをコメントで明示

3. **具体例の選択**
   - プロジェクト全体で一貫した具体例を使用（例: `Project`、`User`など）
   - サンプルコードは実際のプロジェクト構造に即した内容

4. **説明の深さ**
   - 「説明」セクション: 技術的詳細を含む
   - 「意図」セクション: 概念的な目的を説明
   - バランスを取る（どちらか一方に偏らない）

5. **コードサンプルの品質**
   - 完全に動作するコード（または動作に近い形）
   - エラーハンドリングを含む
   - 型安全性を重視
   - コメントは適度に（多すぎず、少なすぎず）

6. **サンプル引用の利点**
   - 冗長性を削減: 各ルールで同じコードを繰り返し記述しない
   - 一貫性の確保: 全体像を最初に示すことで、各ルールの関連性が明確
   - 保守性の向上: サンプルコードの変更が1箇所で済む

### レイヤー別の特記事項

#### Domain層
- 純粋性の強調（副作用なし、外部依存なし）
- 不変性の重視
- ビジネスロジックの集中

#### Application層
- Facade パターンの実装
- Port（インターフェース）の定義
- UseCase の配置

#### Infrastructure層
- Adapter パターンの実装
- データ変換とバリデーション
- エラーハンドリング

#### Presentation層
- コンポーネントの責務分離
- Container/Presentational パターン
- Facade の利用

#### Bootstrap層
- 依存性注入（DI）の実装
- 初期化ロジック
- 環境設定の管理
